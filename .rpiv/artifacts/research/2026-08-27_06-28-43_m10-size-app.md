# Research: M10 size-app — dimensionamiento cuantitativo de apps para preventa

## Research Question

Cadena de `.rpiv/artifacts/discover/2026-08-27_04-15-43_m10-size-app.md` (FRD M10). Enfoque: skill pack `src/tools/frida-size-app/` de 4 archivos (patrón builtin + generador de script + skills/prompts + resolver 3-capas) + installer `ensureBinary` propio (scc@PIN con checksum al agentDir, espejo de `installer.ts` de codebase-index), componiendo el motor intocado. Script generado: `bootstrap → metrics → analyze → synthesize → judge` — determinista al inicio (sondas scc/lizard → `metrics.json` con writer único) y al final (informe derivado solo del inventario), agéntico solo en analyze (fan-out) y judge (detached + checkpoint si `review=manual`). Entregables en `docs/dimensionamiento/` del proyecto dimensionado.

Supuestos del FRD a verificar: (1) scc distribuye binarios por plataforma en GitHub Releases con checksums y matrix suficiente para darwin/arm64 + linux/x64; (2) el NPV de `lizard` (CCN por función polyglota) vs el piso file-level de `scc --cognitive`.

## Summary

El molde de 4 archivos está validado dos veces (M1/M9) y el seam de registro publica el patrón en catálogo/picker sin tocar el motor: `registerBuiltinPattern` (`src/tools/frida-extensible-workflows/builtin-patterns.ts:481`) es un splice/push idempotente sin validación runtime — todo el contrato vive en el pack. La superficie aritmética del sandbox soporta el COCOMO completo (`Math.pow` ✓, `JSON.parse` ✓, `Date`/`Intl` tapados). El installer tiene todos los moldes internos (pin+marker de codebase-index, https+sha256 de frida-cc-plugins) excepto uno: **no existe primitiva de extracción tar.gz en el árbol** — toca implementarla mínima sobre `node:zlib` (más simple que el unzip existente). Externo: **scc v4.0.0** (2026-08-24) es la ÚNICA versión con `--hotspots/--coupling/--by-author/--cognitive` que exige el FRD — v3.4.0 no las tiene; la matrix de assets cubre darwin/arm64 + linux/x64 con `checksums.txt` sha256 único. scc implementa **Basic COCOMO 81** (no COCOMO II) con exponente de calendario **d variable por modo** y overhead 2.4. lizard (terryyin, PyPI) requiere runtime Python — el piso file-level de scc basta para el caso preventa y lizard queda como familia opcional degradada, como decidió discover.

## Detailed Findings

### Publicación del patrón (registro → catálogo → picker)

- El patrón se declara como `BuiltinPattern` (molde `UNDERSTAND_APP_PATTERN` en `src/tools/frida-understand-app/index.ts:88`); la factory `createFridaUnderstandApp` (`src/tools/frida-understand-app/index.ts:121`) clona el patrón con un `resolve` que re-sondea en cada launch con `agentDir`/toggle inyectados.
- `REGISTERED_PATTERNS` (`src/tools/frida-extensible-workflows/builtin-patterns.ts:478`) es un array module-privado; `registerBuiltinPattern` (`builtin-patterns.ts:481`) hace findIndex+splice+push — **idempotente por nombre, gana el último, sin validación runtime alguna** (ni nombre, ni args, ni meta). El contrato lo impone el tipo TS en compile-time (`BuiltinPattern` en `builtin-patterns.ts:375-390`; `meta.moat` en `:366-372`).
- `requireStringArray` existe pero es **privada del motor** (`builtin-patterns.ts:57-68`) y rechaza `[]` vacío — semántica inadecuada para `exclude[]` (que debe aceptar vacío = solo defaults). El pack necesita su propio helper local, como hicieron los hermanos con `asRecord`/`parseReview`.
- Consumo: `findBuiltinPattern` (`builtin-patterns.ts:469`) → el tool `workflow` llama `builtin.resolve(args, { cwd })` en `src/tools/frida-extensible-workflows/index.ts:331` (único call-site del motor); `builtinPatternsCatalog` (`builtin-patterns.ts:499`) expone `{name, description, args, meta?}` al tool `workflow_catalog` (`src/tools/frida-extensible-workflows/index.ts:527`) — sin `name` lista patrones, con `name` devuelve el detalle con instrucción de launch.
- Picker: `/wf` → `handleWfSlash` (`src/extension.ts:4488`) → `pickWorkflow` lee `builtinPatternsCatalog()` (`src/extension.ts:4524`) y muestra el string `args` como `detail` del QuickPick. `frida.showWorkflows` (`src/extension.ts:5955`) abre el panel de runs (no selecciona patrones).
- El string `args` del patrón es **documentación pura** — el motor nunca lo parsea; viaja verbatim a catálogo y picker. El objeto real se valida eager en `resolve()` del pack (dos pisos documentados en `builtin-patterns.ts:18-21`: eager + defensivo en script).
- Wiring de publicación que M1/M9 tocaron: factory en `src/pi-session.ts:670-684` (M1) / `:685-695` (M9) dentro de `extensionFactories` (`pi-session.ts:619`); `HELP_TOOLS` (`src/extension.ts:3906`, entradas M1 `:4065` y M9 `:4075` — matching first-match, alias sin colisión); fila README (`README.md:213-214`, sección `:186`); docs par `docs/tools/*` + `docs/how-to-*`.

### Sonda de capacidades: moat vs datos declarativos

- `BuiltinPattern.resolve` es **síncrona por contrato** (`builtin-patterns.ts:389`) y el motor la invoca sin await (`src/tools/frida-extensible-workflows/index.ts:331`) — `scc --version` (spawn async) NO puede ser parte de la sonda en resolve-time; la verificación por ejecución vive en `ensureBinary` post-install o en runtime del script.
- `detectUnderstandAppCapabilities` (`src/tools/frida-understand-app/index.ts:55-67`) sondea con `piLensEntryPath` (`src/tools/frida-extensible-workflows/moat-factories.ts:59`, única fuente compartida con el motor) + `isInstalledAtPin` AND toggle. El análogo scc: `sccInstalledAtPin(agentDir)` = marker propio (pin+sha256 escrito por el installer; scc no tiene package.json) && `existsSync(binario)` — síncrona.
- `lizard` en PATH: no hay `command -v` en src; la salida limpia es la sonda híbrida — mitad shell en el script (`command -v lizard`, análogo del `test -s` en `src/tools/frida-understand-app/workflow.ts:378`) + opcionalmente escaneo síncrono de PATH host-side.
- `MoatFlags` (`moat-factories.ts:47`) solo tiene `lens`/`codebaseIndex`; `createMoatFactories` (`moat-factories.ts:111-128`) solo lee esas dos claves. **scc/lizard son meros datos declarativos JSON-safe** interpolados como `CAPABILITIES` (molde workflow.ts:239) — cero cambios a moat-factories.ts. Además del booleano, el script necesita la **ruta absoluta del binario pineado** (`SCC_BIN`) interpolada host-side — usar scc del PATH rompería la reproducibilidad del pin.
- Inyección a hijas: `createWorkflowChildFactoriesWithMoat` (`moat-factories.ts:152-166`) → `createFridaAgentSpawner` con `resourceLoader.reload()` obligatorio (`src/tools/frida-extensible-workflows/frida-agent-execution.ts:423`).

### ensureBinary: descarga + integridad + extracción tar.gz

- `ensureInstalled` (`src/tools/frida-codebase-index/installer.ts:170`) NO descarga — delega a npm. El espejo estructural: idempotencia por `isInstalledAtPin` (`installer.ts:71`), `InstallDeps` inyectable, timeout, `CodebaseIndexInstallError` con `guide` accionable (`installer.ts:29`), `manualCmd` con prefix absoluto (`installer.ts:160`), `onProgress`.
- Precedente funcional de descarga: `defaultFetchArchive` (`src/tools/frida-cc-plugins/fetch.ts:185`) — https-only, redirects solo https, límite 256 MiB (`MAX_ARCHIVE_BYTES`, `fetch.ts:26`); **privada** (no exportada). Verificación sha256: `fetch.ts:339-343` (`crypto.createHash("sha256")` contra 64 hex), dentro de `materializeArchive` (`fetch.ts:330`) que es plugin-específica (exige `.claude-plugin/`) — inaplicable a tarballs; hay que **copiar el patrón** (~50 líneas con deps inyectable).
- `unzipSync` (`fetch.ts:126`) SÍ está exportada y cubre el asset win32 (.zip) de scc. **No existe primitiva tar en el árbol**: el único `node:zlib` es `fetch.ts` (inflateRawSync); tar-fs es solo transitive de devDeps. La extracción tar.gz es **más simple que zip** (bloques de 512 bytes, sin central directory; gzip aporta el CRC) — parser mínimo sobre `zlib.gunzipSync` con el mismo guard anti path-traversal de `unzipSync`.
- Orden de verificación: sha256 del archivo comprimido ANTES de extraer (espejo fetch.ts:339-343), extracción, copia del binario a `<agentDir>/bin/scc`, `chmodSync 0o755` en no-win32, marker de pin.
- Disparo: `resolve()` es síncrona → `ensureBinary` (async) no puede correr ahí. Molde fire-and-forget: `src/tools/frida-hermes-memory/index.ts:181-190` (`void doEnsureInstalled(...).then(...).catch(...)` — nunca bloquea ni tumba la sesión). La corrida queda protegida por `CAPABILITIES.scc=false` + degradación determinista en metrics.
- `constants.ts` propio espejando codebase-index: `SCC_PIN` (análogo `CODEBASE_INDEX_PIN`, `src/tools/frida-codebase-index/constants.ts:13`), tabla explícita plataforma→asset (análogo `PLATFORM_NATIVE`, `constants.ts:51-57` — **con la lección copiada: los sufijos NO son derivables uniformemente, la versión con endsWith rompió win32-x64**), `SCC_DIGESTS` asset→sha256 (sin análogo directo: codebase-index delega integridad a npm), `currentSccAsset()` con `undefined` → degradación (molde `currentPlatformNative`, `constants.ts:66-71`).
- Bump deliberado: editar juntos `SCC_PIN` + `SCC_ASSETS` + `SCC_DIGESTS`, verificado contra el release real (disciplina "subir versión es deliberado", `constants.ts:9`).
- Tests sin red: `deps: { fetchArchive: async () => buffer }` con fixture tar.gz armada en el test (más simple que `makeZip` — gzip calcula su propio CRC), `platform`/`arch` inyectables (molde `test/frida-codebase-index/installer.test.ts:80-83`), negativo de integridad con sha malo (molde `test/frida-cc-plugins/phase2.test.ts:403-435`).

### Fases deterministas: metrics + synthesize en el sandbox

- Writer único M1: `inv` (`src/tools/frida-understand-app/workflow.ts:305`) + `invSerialize`/`invWrite` + `writeText` heredoc con fence por-patrón (workflow.ts:262-270; M9 usa `T2A_EOF` en `src/tools/frida-traffic2api/workflow.ts:620-624`); `registerDegradations` (workflow.ts:337-346) es el canal único para emisor determinista (bootstrap) Y agéntico (analyze). Size-app normaliza N sondas scc a `metrics.json` con degradación por familia `{familia, causa, hint}`.
- Sandbox (`src/tools/frida-extensible-workflows/core/execution.ts:319-323`): `JSON` y `Math` inyectados (`safeMath` sin `random`), intrínsecos estándar disponibles (`Array.sort/reduce/filter`, `parseInt`, `**`), **tapados con undefined**: `Date`, `Intl`, `console`, `setTimeout` entre 22 nombres. `Math.pow` disponible → COCOMO computable al 100%. `RESERVED_GLOBALS` (`src/tools/frida-extensible-workflows/core/registry.ts:8`) es solo lista negra de colisión para nombres de funciones de extensión, NO el scope del sandbox.
- **Límite RPC de 10 MB** (`RPC_LIMIT_BYTES`, `execution.ts:45`) en stdout de shell, mensajes IPC y valor de retorno; heap del child 128 MB (`execution.ts:692`). El molde para JSON grande es la fase ingest de M9 (`src/tools/frida-traffic2api/workflow.ts:950-970`): helper `node` escrito a disco que corre EN EL HOST, lee el archivo gordo de disco, escribe artefactos y devuelve solo un resumen delgado (`JSON.parse(r.stdout)`, `workflow.ts:644`). `scc --by-file --format json` sobre ~1M LOC puede rebasar 10 MB → mismo patrón. Vía corta para repos chicos: parseo directo (molde abRun).
- Tiempo sin Date: `epochNow()` (workflow.ts:276-278 vía `date +%s`), deadline `startedAtEpoch + maxMinutes*60` (workflow.ts:386-387), guards en `:396` y `:443` — el wall-clock corta el descubrimiento, las fases de entregable siempre corren (header workflow.ts:22-23).
- synthesize determinista M1: derivación pura desde el inventario (`m4m5Verdict`), ensamblado `md.push` + `writeText`, tablas con `mdCell`, sin Intl (tabla manual de acentos de `slug()`, workflow.ts:286-293; formatos de monto: función manual o `toFixed`). Sin Intl, ordenamientos con tie-break binario determinista (molde M9 `sort(count desc || alfabético)`).
- M9 añadió gates de forma post-escritura con `node -e` y asignación de IDs estables DESPUÉS de ordenar — el patrón para IDs de olas/hotspots.

### Fases agénticas: analyze fan-out + judge

- `parallel()` exige exactamente 2 args: literal string + ObjectExpression RECORD (`src/tools/frida-extensible-workflows/core/validation.ts:700`); runtime `Promise.all` — un fallo de task aborta el parallel completo tras esperar a todas (error de la primera task fallida en orden de record). La tolerancia a flakiness es del ARTEFACTO, no del transporte: gates `test -s` + reintento único informado con runtime block "FALLA ANTERIOR" (molde completo workflow.ts:468-497), throw con `ls -la` diagnóstico si persiste.
- `agent()` requiere call-site directo: `instrumentWorkflow` (`validation.ts:416-439`) reescribe `agent(...)` a un identificador interno añadiendo `"start:end"` como último argumento — identidad persistente para resume/retry (`agentIdentityPath`) y veto anti-fanout no controlado (`validateObviousConcurrentAgentCalls`, `validation.ts:369`; `agentInflight` en execution.ts). `.map(async () => agent())` está prohibido.
- **El fan-out de size-app es determinista en su forma** (a diferencia del dinámico de M1, que deriva de `areas[]` de un LLM): las tasks derivan de `metrics.json` — top hotspots por score complejidad×churn, deuda por módulo, riesgos de tamaño son funciones puras del JSON. El e2e puede predecir claves/rutas sembrando un `scc` falso en PATH (molde `.mock-bin`, `test/frida-understand-app/e2e.test.ts:55`).
- Juez: prompt del stage `judge` con rúbrica PASS/CONCERNS/FAIL (molde `src/tools/frida-understand-app/skills.ts:151`), veto de solo-escritura en el preamble no-stage (`skills.ts:39`) que sobrevive overrides, `JUDGE_SCHEMA` idéntico M1↔M9 (`src/tools/frida-traffic2api/workflow.ts:606`) — tercera reutilización textual. La regla cut→CONCERNS vive DOS veces (prompt default + runtime block, workflow.ts:709-711) para sobrevivir a overrides.
- Detached real: cada `agent()` crea sesión nueva in-memory (`frida-agent-execution.ts:411-470`); el motor prohíbe pasar resultados previos por conversación.
- El juez de NÚMEROS: cada cifra o está en metrics.json tal cual o se re-deriva con la fórmula declarada — no hay tercera opción. Familia declarada sin sustento = FAIL CRITICAL/HIGH; familia degradada o corte por presupuesto = CONCERNS.
- Test de dominio COCOMO (molde `test/frida-traffic2api/openapi-schema.test.ts`): schema test-local del bloque COCOMO con **tres números no uno**, fixtures numéricas precomputadas, anti-fixtures (exponente del modo equivocado, EAF fuera de banda, rango no-creciente, wage ausente), y corrida e2e con scc falso verificando que dimensionamiento.md contiene exactamente los números derivados.
- Test "mentiroso" del juez (molde `test/frida-understand-app/e2e.test.ts:652-676`, ancla `:266-267`): mock que matchea "## Entregables a auditar", rama FAIL con evidence citando informe vs metrics.json; el veredicto viaja en el return SIN abortar.

### Superficies externas: scc v4.0.0, lizard, COCOMO

- **Último release: scc v4.0.0** (2026-08-24). Assets: `scc_Darwin_arm64.tar.gz`, `scc_Darwin_x86_64.tar.gz`, `scc_Linux_arm64/i386/x86_64.tar.gz`, `scc_Windows_arm64/i386/x86_64.zip`, `checksums.txt` — nomenclatura SIN versión embebida, SO con mayúscula inicial, Unix tar.gz / Windows zip (goreleaser: `{{ .ProjectName }}_{{- title .Os }}_…`, amd64→x86_64). Matrix cubre darwin/arm64 + linux/x64 ✓ (y más). Binarios ~6.3-7.2 MB (v3.4.0: ~2.5 MB — creció por go-git embebido).
- `checksums.txt`: 8 líneas `<sha256>  <asset>` (dos espacios, formato sha256sum, sin header), cubre los 8 binarios. **No existe** `checksums.txt.bus`. Licencia MIT (volvió a MIT-only en v3.4.0). URL: `https://github.com/boyter/scc/releases/download/v4.0.0/<asset>`.
- **Las flags `--hotspots --coupling --by-author --cognitive` son NUEVAS de v4.0.0** — no existen en v3.4.0. `--hotspots`/`--coupling`/`--by-author` leen la historia git **in-process con go-git** (sin `git` en PATH), ventana default `--depth 1000`; fuera de un repo git el reporte se omite (degradación natural).
- Salidas (`processor/`): `--by-file --format json` → array de LanguageSummary con array `Files` de FileJob (`Location/Language/Lines/Code/Comment/Blank/Complexity/Cognitive/WeightedComplexity/Bytes/Uloc/Minified/Generated` — nota: `Generated` existe por archivo). `-a` = DRYness+ULOC (DRYness = ULOC/SLOC; penaliza ~2x runtime). `--hotspots` CSV: `File,Language,Complexity,Commits,LinesChanged,Authors,CodeChurn,CommentChurn,Score` (Score = complejidad×commits normalizado 0-100). `--coupling` CSV: `FileA,FileB,Shared,CommitsA,CommitsB,Degree` (umbrales: Shared≥2, commits con >30 archivos excluidos). `--by-author` CSV: `Author,Email,Code,Complexity,Comment,Files,OwnsPercent,LastCommit,BeforeWindow` + bus factor. `--cognitive` = **nivel archivo** (sin AST).
- Exclusiones: `--exclude-dir` (default `[.git,.hg,.svn]`, aditivo), `--exclude-ext`, `--exclude-file` (lockfiles), `-M` regex. **node_modules NO se ignora por defecto como caso especial** — se excluye en la práctica porque scc respeta `.gitignore`/`.ignore`/`.sccignore` por default (desactivable). La default curada del FRD sigue siendo necesaria (un repo sin gitignore de node_modules contaría vendoreado).
- **lizard**: paquete canónico `terryyin/lizard` (PyPI `lizard` 1.24.0, ago-2026, MIT, Python ≥3.8 — **requiere runtime Python, no hay binario único**). `--csv`: una fila por función SIN header (header solo con `-V`): `NLOC,CCN,token,PARAM,length,location,file,function,long_name,start,end`. ~26 lenguajes. Sin benchmark publicado en ~1M LOC (estimación honesta: minutos, vs ~743 ms de scc sobre 28M LOC del kernel). **Recomendación**: scc como fuente de verdad de tamaño/costo; lizard opcional para distribución CCN por función (X% de funciones > CCN 15) — no mezclar sus NLOC con el SLOC de scc en el COCOMO.
- **COCOMO**: scc implementa **Basic COCOMO 81** (Boehm 1981), no COCOMO II. Constantes en `processor/cocomo.go`: organic {2.4, 1.05, 2.5, 0.38}, semi-detached {3.0, 1.12, 2.5, **0.35**}, embedded {3.6, 1.20, 2.5, **0.32**} — E = a·KSLOC^b·EAF (persona-mes), TDEV = 2.5·E^d con **d variable por modo**, personas = E/TDEV, costo = E·(avg-wage/12)·overhead con **overhead 2.4** y `--avg-wage` **anual** default 56286 USD (herencia SLOCCount; NO existe flag `--cost`). `--cocomo-project-type` acepta custom `"tipo,a,b,c,d"`. EAF default 1.0 (`--eaf`).
- **EAF 0.85-1.15 NO es banda documentada**: lo documentado (Intermediate COCOMO, Wikipedia EN) es "típicamente 0.9 a 1.4"; drivers individuales 0.70-1.65. El spread 0.85/1.00/1.15 queda como supuesto conservador del analista, etiquetado en el informe (decisión del checkpoint).

## Architecture Insights

- **El motor no se toca**: `registerBuiltinPattern` no valida nada en runtime; M9 entregó con "motor intacto (0 líneas)" reutilizando el seam de M1. Si el plan de M10 pide tocar `frida-extensible-workflows`, es señal de alerta.
- **Dos pisos de contrato de args** (header `builtin-patterns.ts:18-21`): string `args` declarativo (catálogo/picker — lo que el agente principal lee para preguntar ANTES) + validación eager en `resolve()` (la red de seguridad con instrucciones). El piso defensivo vive interpolado en el script generado.
- **Sonda síncrona vs ejecución async**: `resolve()` es síncrona — todo sondeo por ejecución (`scc --version`, `command -v lizard`) vive fuera de resolve (fire-and-forget post-install o runtime shell del script). El patrón de dos mitades (const host-side + confirmación runtime) es LA plantilla de bootstrap.
- **El sandbox provee Math/JSON e intrínsecos, tapa Date/Intl** — COCOMO y percentiles computables; formatos de moneda manuales; determinismo por tie-break binario.
- **RPC 10 MB es la restricción dominante de la fase metrics**: JSON grande se procesa host-side con helper node (molde carve M9), stdout delgado al sandbox.
- **Fan-out determinista en su forma**: a diferencia de M1 (areas[] de un LLM), las tasks de analyze derivan de metrics.json — testeable sembrando el insumo, sin mockear decisiones de LLM.
- **Pin+digest ES el contrato de reproducibilidad**: el par `SCC_PIN` + `SCC_DIGESTS` (sin digest, el pin es solo una etiqueta). El binario se invoca por ruta absoluta interpolada, jamás del PATH.
- **COCOMO replicando scc exacto** (decisión del checkpoint): constantes {a,b,c,d} por modo con d=0.35 semi-detached, costo = PM·wage·overhead 2.4 con wage mensual preguntado, etiqueta "Basic COCOMO 81 (Boehm)" — números idénticos a la salida nativa de scc, una sola verdad en el artefacto.
- **Degradación honesta por familia** con el mismo canal `registerDegradations` para emisor determinista y agéntico; scc respeta `.gitignore` por defecto — la default curada del FRD es necesaria y el volumen excluido debe medirse explícitamente (p. ej. scc sobre las rutas excluidas) para declararlo en el informe.
